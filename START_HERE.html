ALICEDOT PROJECT MANAGER

대표님들과 함께 사용하는
프로젝트·매출 관리

기존 시안의 화면을 유지한 공동 수정 버전입니다. 계정을 연결하면 같은 자료를 함께 조회하고 수정할 수 있습니다.

현재는 연결 전입니다. 아래 설정을 마치기 전에는 실제 로그인이 되지 않습니다. GitHub 저장소 주소와 Supabase 프로젝트의 공개 연결 정보를 준비해 주시면 설정을 이어갈 수 있습니다.

1. 공용 저장소 만들기

  1. Supabase에서 회사용 새 프로젝트를 만듭니다. 데이터베이스 비밀번호는 직접 정하고 별도 보관합니다.
  2. SQL Editor에서 001_schema.sql 파일 전체를 붙여 넣고 한 번 실행합니다. 이 스크립트는 새 프로젝트용입니다.
  3. Authentication → Users → Add user → Create new user에서 포키님과 대표님들의 이메일·초기 비밀번호로 계정을 만듭니다. 관리자가 확인한 이메일만 등록하고 Auto Confirm User를 사용합니다.
  4. 002_members.example.sql의 이메일과 이름을 구성원별로 바꿔 SQL Editor에서 실행합니다. 모두 동일하게 입력·수정할 수 있습니다. 실행 뒤 members 표에서 등록된 사람 수를 확인합니다.
  5. 이 앱에는 공개 회원가입 기능이 없습니다. Auth 설정의 공개 신규 가입도 끄는 구성을 권장합니다. 이메일 발송 없이 관리자가 계정을 생성하는 초기 설정 방식입니다.

초기 비밀번호는 각 당사자에게 안전하게 전달하고 첫 로그인 후 앱의 비밀번호 변경에서 본인이 변경합니다. 로그인 비밀번호·DB 비밀번호·secret 키를 채팅에 보내실 필요는 없습니다.

2. 화면과 저장소 연결하기

  1. Supabase 프로젝트의 Project URL과 Publishable key를 확인합니다.
  2. config.js를 메모장으로 열고 빈 따옴표 안에 두 값을 넣습니다.
window.ALICEDOT_CONFIG = {
  supabaseUrl: "https://프로젝트ID.supabase.co",
  supabasePublishableKey: "sb_publishable_공개용키"
};

공개용 키는 화면 연결에 사용하며, 실제 자료 접근은 로그인과 DB 권한으로 제한합니다. secret 또는 service_role 키는 넣지 않습니다.

3. GitHub에 올리기

  1. 프로그램 저장소는 FORKY-G/alicedot입니다.
  2. 프로그램의 배포 파일 전체를 저장소 맨 위에 올립니다. index.html이 최상단에 있어야 합니다. 실제 엑셀과 회사 자료는 올리지 않습니다.
  3. 저장소 Settings → Pages → Deploy from a branch에서 main, /(root)를 선택해 저장합니다.
  4. GitHub가 제공하는 Pages 주소로 접속합니다. 로그인 화면에서 각각 자신의 계정으로 로그인합니다.

GitHub 요금제·저장소 공개 범위에 따라 Pages 사용 조건이 달라질 수 있습니다. 앱 화면 자체는 공개 URL에 있어도 회사 데이터는 구성원 인증을 통과해야 표시됩니다.

4. 공동 사용 확인 후 기존 자료 가져오기

  1. 각기 다른 브라우저에서 포키님 계정과 대표님 계정으로 로그인합니다.
  2. 테스트 프로젝트 한 건을 만들고 양쪽 화면에서 보이는지 확인합니다. 다른 쪽은 새로고침하거나 최대 20초 기다립니다.
  3. 대표님 계정에서 상태·금액을 수정하고 포키님 화면 및 수정 이력에 반영되는지 확인합니다. 같은 프로젝트를 동시에 수정하면 나중 저장이 거절되어야 합니다.
  4. 미등록 계정에서는 회사 자료가 표시되지 않는지 확인합니다.
  5. 엑셀 가져오기에서 원본 견적서를 선택합니다. 시트·연도·금액·날짜 안내를 검토한 후 공유 공간에 저장을 누릅니다. 원본 파일은 변경되지 않습니다.

원본에 달력상 없는 결제일이 있으면 임의 날짜로 바꾸지 않고 메모에 원문을 남깁니다. 가져온 뒤 해당 날짜를 확인해 주세요.

평소 사용은 간단합니다

새 프로젝트로 등록하고, 작업상태를 바꾸며, 상세에서 금액과 날짜를 수정합니다. 월·상태·거래처로 찾을 수 있고, 캔슬은 실매출·미지급금에서 자동 제외됩니다.

잘못 등록한 건은 보관하기로 옮기고 필요하면 복원합니다. 수정 이력은 상세 화면에서 확인합니다.

연결 없이 화면만 살펴보려면 예시 시안 열기를 이용하세요. 예시 화면의 데이터는 실제 공유 공간과 별개입니다.

계산 기준·가져오기 중복 처리·개발 및 백업 안내는 README.md에 정리했습니다.
