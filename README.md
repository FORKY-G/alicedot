# AliceDot 프로젝트 관리 · 공동 수정 버전

승인된 회사 구성원이 함께 사용하는 견적·매출 관리 웹앱입니다. 포키님과 대표님 모두 등록·수정할 수 있습니다.

현재 상태: 공동 수정용 앱과 데이터베이스 설치 스크립트를 이 저장소에 준비했습니다. Supabase 연결 전이며, 연결과 구성원 등록이 끝나면 실제 이메일/비밀번호 로그인 및 다중 기기 동기화를 확인합니다.

## 설치

설치 순서는 `START_HERE.html`에서 확인하세요. GitHub Pages는 main 브랜치의 루트에서 제공합니다.

- `index.html`, `app.js`, `styles.css`, `config.js`: 이미 빌드된 배포 파일.
- `preview.html`: 실제 회사 자료와 분리된 예시 시안.
- `001_schema.sql`, `002_members.example.sql`: Supabase SQL Editor에서 실행할 DB 설치 및 구성원 등록 예시.
- `alicedot-source.zip`: 전체 개발 소스와 테스트. 압축 해제한 `source/` 폴더에서 개발합니다. 사용자 자료/비밀키는 포함하지 않습니다.

GitHub는 프로그램 화면을, Supabase는 인증과 프로젝트 자료를 담당합니다. GitHub Pages의 웹 화면은 공개 접속 가능하지만 회사 자료는 로그인 및 DB 구성원 권한 검사를 통과해야 조회할 수 있습니다. 저장소를 비공개로 바꾸는 것만으로 Pages 웹페이지가 비공개가 되는 것은 아닙니다.

## 사용

- 연도·월 선택: 상단 합계와 목록을 해당 기간으로 조회합니다.
- 검색·상태 선택: 목록만 필터링합니다. 상단 합계는 선택 기간 전체 기준입니다.
- 최초 등록일: 새 프로젝트를 저장할 때 한국 날짜로 기록하고 이후 수정해도 유지합니다.
- 다른 사람의 변경: 화면이 열려 있는 동안 20초마다, 다시 화면에 돌아올 때, 새로고침 버튼을 누를 때 조회합니다.
- 동시 수정: 같은 버전을 열어 두 사람이 저장하면 먼저 저장한 변경을 유지합니다. 나중 저장은 거절하고 입력 내용을 화면에 남깁니다. 필요한 내용을 복사해 둔 뒤 상세 창을 다시 열어 최신 자료를 보고 수정합니다.
- 보관함: 보관한 프로젝트는 집계에서 제외되고 복원할 수 있습니다. 영구 삭제 기능은 없습니다.
- 수정 이력: 프로젝트 상세에서 변경자·시간·내용을 봅니다. 화면은 최근 100개를 보여주며 DB에는 전체 이력을 남깁니다.
- CSV: 현재 목록을 내려받습니다. DB 전체 백업/복원 파일은 아니며 보관함·수정 이력·계정 정보는 포함하지 않습니다.

## 계산 기준

| 항목 | 기준 |
|---|---|
| 예상매출 | 최초견적 전체 합계, 캔슬 포함 |
| 실매출 | 캔슬 제외 최종견적 합계 |
| 결제완료 | 결제완료 상태의 최종견적 합계 |
| 미지급금 | 결제완료·캔슬 제외 최종견적 합계 |
| 계산서 발행액 | 입력한 계산서 금액 합계 |

보관함의 기록은 모든 합계에서 제외합니다. 최초/최종견적 미정은 빈칸으로 보존합니다. 부가세를 자동 계산하거나 더하지 않고 입력 금액을 그대로 합산합니다. 부분 입금·분할 계산서 발행 내역은 별도 행으로 관리하지 않는 1차 버전입니다.

## 기존 엑셀 가져오기

기존 AliceDot 월별 양식(.xlsx)을 선택하고 연도·시트를 확인한 다음 미리보기를 검토합니다. `공유 공간에 저장`을 눌렀을 때만 DB로 전송됩니다. 파일 선택만으로 외부에 전송하지 않습니다.

매핑: B 월 / D 등록일 / E 프로젝트 / F 대행사 / G 프로덕션 / H 감독 / I PD / J 상태 / K 최초견적 / L 최종견적 / M 결제일 / O 계산서 발행일 / P 계산서 금액 / Q 상호명 / R 메모. N열의 견적서 링크/첨부는 이번 버전에서 가져오지 않습니다. 월별 소계와 상단 합계는 제외합니다.

금액 오류가 있으면 저장을 막습니다. 잘못된 결제일·계산서 발행일은 빈 날짜로 두고 원문을 메모에 남기며 사전에 안내합니다. 등록일이 비어 있으면 가져오는 날짜를 사용한다고 안내합니다. 잘못된 등록일은 오류로 표시합니다. 원본 파일은 수정하지 않습니다.

시트명+집계 연도+원본 행번호가 같은 이전 가져오기는 중복으로 건너뜁니다. 기존 자료를 갱신하거나 덮어쓰지 않습니다. 표의 행 위치가 바뀐 파일을 다시 가져오는 갱신 방식은 지원하지 않으므로, 최초 이관 후 수정은 앱에서 해 주세요. 한 파일은 최대 15MB, 한 번에 1,000건입니다.

## 개발 및 검증

`alicedot-source.zip`을 압축 해제한 `source/` 폴더에서 진행합니다. Node.js 22 이상에서 `npm ci`, `npm test`, `npm run build` 순서로 실행합니다. 생성된 `dist/`를 배포합니다. `public/config.js`의 공개용 연결값을 수정하면 다음 빌드에 반영됩니다. 단순 배포 사용자는 `config.js`만 수정해도 됩니다.

PGlite(PostgreSQL)에서 실제 SQL을 실행하여 익명/비구성원 차단, 구성원 공동 수정, 직접 테이블 변경 금지, 서버 이력, 등록일 유지, 버전 충돌, 보관/복원, 가져오기 중복 방지 및 트랜잭션 취소를 검증했습니다. 브라우저 화면은 모의 API로 등록·수정·합계·이력·보관/복원을 검증했습니다. 실제 Supabase Auth/PostgREST 연결은 배포 후 검증이 필요합니다.

`scripts/build-qa.mjs`와 `tests/qa-api.js`는 개발 검증 전용입니다. QA 빌드 산출물을 배포하지 마세요. 정상 배포는 반드시 `npm run build` 산출물을 사용합니다.

자료 백업은 회사가 정한 주기로 Supabase DB 전체를 별도 보관하고 복원 확인을 해야 합니다. 이 앱에서 자동 백업 작업을 설정하지는 않았습니다.
